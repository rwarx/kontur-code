# Kontur Code

[English version](README.md)

Нативный настольный LLM-клиент для Windows, который эволюционирует в среду пространственной
разработки с ИИ. Одно окно, ваши собственные API-ключи, переписка в локальном файле SQLite и
рабочая область, превращающая указанную папку в граф, который видно.

Архитектура ровно та, которую требует ИИ-IDE: домен ничего не знает про HTTP, интерфейс не может
дотянуться до провайдера, стриминг идёт сквозь всё как `IAsyncEnumerable<T>`. Функциональность -
рабочая область, агент, графический холст и цикл инструментов, который читает и правит файлы под
вашим контролем. Агент видит и меняет репозиторий через свои git-инструменты; полноценный редактор
кода - следующий этап.

## Что умеет

- **Стриминговый чат.** Токены появляются по мере поступления. Остановка посреди ответа сохраняет
  частичный текст, а не выбрасывает его. Повторная генерация заменяет ответ на месте - при желании
  на другой модели.
- **Голосовой диктовщик.** `Ctrl+M` (или кнопка с микрофоном) диктует в поле ввода на машинах с
  распознаванием речи Windows; если его нет, приложение честно об этом сообщает.
- **Режим агента.** Одна кнопка в редакторе сообщения решает, чем станет следующий запрос - планом,
  планом на холст, сборкой или обычным сообщением - и отправляет его в цикл инструментов, а не
  сразу модели. По умолчанию включён план: «сборка» умеет листать, читать, искать, писать, править,
  перемещать и удалять файлы, запускать разрешённые программы и работать с git в пределах одной
  указанной папки, спрашивая перед каждым изменением; план ничего не пишет и не трогает. См.
  [Режим агента](#режим-агента).
- **Графический холст.** Пространственный вид проекта: файлы, папки, модули, сервисы, интерфейсы и
  планы становятся узлами бесконечного холста. Перетаскивание, зум, панорамирование, выделение и
  связи. Граф сохраняется вместе с рабочей областью и переживает перезапуски. Планы агента
  рисуются прямо на холсте набором узлов и рёбер - остаётся подтвердить или отклонить.
- **Поверхности рабочей области.** Одна и та же область говорит на разных языках: холст -
  пространственная карта, граф - структура, дерево файлов, read-only просмотрщик кода для открытых
  документов, сам разговор, каталог провайдеров и экран задач активности агента - в одно нажатие
  через палитру команд или боковую панель (`Ctrl+Shift+P`).
- **Индексатор рабочей области.** Папка сканируется и автоматически отображается в узлы графа -
  код, представления, данные, тесты, внешние ссылки - с рёбрами вложенности и зависимостей.
  Раскладка сохраняет ваше расположение карточек при обновлениях.
- **Панель контекста.** Потребление токенов, оценка стоимости, разбор того, что держит модель, и
  кнопка **Сжать сессию**, складывающая старые сообщения в сводку, когда окно почти заполнено
  (`Ctrl+Alt+I` показывает и прячет панель).
- **Markdown и код.** Заголовки, списки, таблицы, цитаты и блоки кода рендерятся как элементы WPF,
  а не как HTML в браузерном контроле, с подсветкой синтаксиса для распространённых языков.
- **Сессии.** Создание, переименование, закрепление, поиск и удаление переписок. Название
  генерируется из первого сообщения, пока вы не зададите своё.
- **Каталог моделей.** Загружается у каждого провайдера и кэшируется в SQLite: пикер открывается
  мгновенно и работает без сети. Окно контекста, цены, стриминг, поддержка картинок и инструментов
  приходят от провайдера, а не из жёстко прописанного списка.
- **Провайдеры.** OpenRouter и NVIDIA NIM из коробки, оба совместимы с OpenAI. Проверьте соединение
  до того, как положитесь на него.
- **Вложения.** Текстовые и исходные файлы читаются, ограничиваются по размеру и вставляются в
  промпт. Бинарники отклоняются, даже если их переименовать в `.txt`.
- **Экспорт.** Переписка в Markdown, JSON или обычный текст.
- **Настройки.** Внешний вид, язык интерфейса, параметры чата и сэмплирования, хранилище и лимиты
  вложений, папка агента и его бюджеты - всё хранится локально.
- **Три языка.** Английский, русский и немецкий: выбираются в Настройки → Основные → Язык и
  применяются ко всему интерфейсу на лету.
- **Fluent-оболочка.** Светлая, тёмная тема или следование системе, фон Mica, палитра команд.

## Требования

- Windows 10 версии 1809 или новее либо Windows 11
- [.NET 10 SDK](https://dotnet.microsoft.com/download) для сборки; для запуска опубликованной
  сборки достаточно рантайма
- API-как минимум одного из поддерживаемых провайдеров

## Сборка и запуск

```bash
dotnet build AIClient.slnx
```

```bash
dotnet run --project src/AIClient.App
```

Чтобы получить сборку, которую можно перенести на другую машину:

```bash
dotnet publish src/AIClient.App -c Release -r win-x64 --self-contained false
```

## Первый запуск

1. Запустите приложение. Экран первого запуска предлагает провайдер и ключ.
2. Вставьте ключ. Он шифруется DPAPI и сохраняется в вашем профиле - никогда в репозитории, базе
   или логе.
3. **Обновить** загружает каталог моделей. **Проверить соединение** подтверждает ключ, не тратя
   токены.
4. Выберите модель и начните печатать. Выбор запоминается как значение по умолчанию для новых
   чатов.

Позже то же самое делает Настройки → Провайдеры - там же ключ заменяется или удаляется.

## Режим агента

**Agent** в редакторе открывает меню: что делать со следующим сообщением - **План**, **План +
холст**, **Сборка** или **Выкл.** - и любой из трёх вариантов уводит запрос в цикл, а не в одно
completion. Модель получает набор инструментов, запрашивает нужные, видит результаты и продолжает,
пока не получит ответ или не исчерпает бюджет. Транскрипт показывает работу: одна карточка на вызов
с кратким описанием аргументов, исходом и результатом под шевроном.

Тип запуска выбирается для каждого сообщения, а не один раз на всю сессию - план, прочитать план,
затем сборка - и по умолчанию стоит **План**: первое, что делает режим для нового пользователя, -
рассказать, что он собирается делать, а не сразу делать. Кнопка показывает активный режим, пока
меню закрыто: разница между чтением папки и её переписыванием стоит того, чтобы увидеть её до
нажатия Send. **Выкл.** возвращает обычное сообщение и запоминает последний выбранный режим.

| Режим | Может | Не может |
| --- | --- | --- |
| **План** | Читать папку и записывать план через `submit_plan` | Писать, перемещать, удалять, запускать и коммитить |
| **План + холст** | То же, и передать план как части и зависимости для отрисовки на графе | То же |
| **Сборка** | Всё из таблицы ниже, спрашивая первым делом там, где так указано | Записывать план - это для двух других режимов |

Режим не «рекомендация», а правило: недоступные инструменты вынимаются из запроса, а пришедший
вызов отклоняется до чтения аргументов. Отказ - это фраза, на которую модель может среагировать, а
не ошибка: запланированный прогон, полезший в `write_file`, получает «закончи план», а не обрыв.

**План + холст** записывает структурированный план и передаёт его в `CanvasPlanSink`, который
собирает `GraphChangeSet` (узел плана + узлы-части + рёбра) и спрашивает подтверждение перед
отрисовкой. После подтверждения план становится частью графа: его можно отменить, он сохраняется и
виден рядом с узлами рабочей области.

**Сборка** - единственный режим, которому нужна папка; выбор её без открытой папки запрашивает,
какую открыть. Эта папка - весь предел досягаемости агента: она запоминается между сессиями,
показывается под редактором, пока режим включён, и меняется или закрывается в Настройки → Агент.
Отмена выбора возвращает в План, а не выключает агента. Планирование без открытой папки - не
деградация, а обычное состояние проекта, которого ещё нет: читать нечего, поэтому план берётся из
того, что вы ему рассказали.

| Инструмент | Делает | Спрашивает сначала |
| --- | --- | --- |
| `list_files` | Листает каталог, игнорируя `.git`, `bin`, `obj`, `node_modules` и подобные | Нет |
| `read_file` | Читает текстовый файл с лимитом размера и, опционально, диапазоном строк | Нет |
| `search_files` | Ищет по содержимому файлов - буквально или регуляркой, до 150 совпадений | Нет |
| `submit_plan` | Записывает план - заголовок, шаги, создаваемые части, риски - и завершает прогон | Нет, и только в режиме планирования |
| `write_file` | Создаёт или перезаписывает файл | Да |
| `edit_file` | Заменяет точный фрагмент в файле | Да |
| `create_directory` | Создаёт папку | Да |
| `move_file` | Перемещает или переименовывает | Да |
| `delete_file` | Удаляет файл или пустую папку | Да |
| `run_command` | Запускает одну разрешённую программу в папке и возвращает вывод и код выхода | Да |
| `git_status` | Ветка, отставание/обгон трекинга и каждый изменённый файл со стадием/анстейджем | Нет |
| `git_diff` | Unified-диф стадиженых изменений, нестадиженых, одного файла или двух рефов | Нет |
| `git_commit` | Индексирует все изменения и создаёт коммит с переданным сообщением | Да |
| `git_checkout` | Создаёт новую ветку от HEAD и переключается на неё или на существующую | Да |
| `git_revert` | Создаёт новый коммит, отменяющий прежний; без аргумента - последний коммит | Да |

Чтения за пределами папки отклоняются, как и пути с креденшелами и внутренностями
контроля версий - `.git`, `.env`, файлы ключей и сертификаты - будь то прямое имя, выход через `..`
или симлинк наружу. Git-инструменты работают с репозиторием, содержащим папку, и не выходят за его
пределы.

Каждый инструмент с *Да* останавливается и спрашивает - каждый раз. Первый строкой называет
эффект: `Create src/Widget.cs`, `Overwrite 42 lines in src/Widget.cs`, `Delete docs/old.md`; под
правкой или перезаписью лежит диф. **Approve** применяет, **Deny** выдаёт модели отказ, на который
можно среагировать и продолжить, а остановка прогона помечает открытое как прерванное, не гадая,
успело ли попасть на диск. Переключателя «одобрить всё» нет.

`run_command` - тот единственный, что выходит за пределы папки, поэтому огорожен иначе. Он выключен,
пока вы не включите его в Настройки → Запуск программ; работать могут только программы из вашего
списка - `dotnet`, `git`, `npm` и другие тулчейны - по имени и никогда по пути. Оболочки нет:
программа запускается напрямую со списком аргументов, поэтому `&&`, `|`, `>` и `$HOME` - текст для
неё, а не синтаксис, и оболочки в списке нет сознательно: разрешив её, вы бы сделали остальной
список декоративным. Согласование спрашивается на каждый вызов и никогда не запоминается - десять
команд это десять вопросов, - а диалог показывает программу и каждый аргумент целиком, потому что
флаг, делающий команду разрушительной, лежит в аргументах. Тем, что программа делает после
запуска, рулит ваша учётная запись, а не рабочая область - поэтому это решение, а не значение по
умолчанию.

Три бюджета в настройках ограничивают прогон: шагов на сообщение (25), лимит времени (10 минут,
0 - без лимита) и самый большой файл, который агент может открыть (512 КБ). У команды два своих:
сколько она может работать до убийства (2 минуты) и сколько вывода сохраняется (20 000 символов -
конец, а не начало, потому что именно там сборка говорит, что пошло не так). Если модель предлагает
один и тот же вызов три раза подряд, она об этом узнаёт, а не крутится в цикле.

## Где живут ваши данные

Всё лежит в `%APPDATA%\AIClient`, и машину не покидают ни токены, кроме запросов к выбранному
вами провайдеру.

| Путь | Содержимое |
| --- | --- |
| `aiclient.db` | Переписки, сообщения, вложения, кэш моделей, настройки |
| `secrets\<provider>.dat` | Один API-ключ на провайдер, зашифрованный DPAPI |
| `logs\` | Ротирующиеся логи, по умолчанию семь дней |
| `attachments\` | Копии прикреплённых файлов, когда опция включена |

Телеметрии нет, аккаунтов нет, синхронизации нет.

Папка, которую вы дали агенту, - единственное исключение: это место, которое вы выбрали, агент
пишет туда напрямую, и под `%APPDATA%` хранится только его путь. Внутреннее хранилище приложения
ничего не копирует, поэтому откат изменения агента - работа для вашей системы контроля версий, а не
для этого приложения.

## API-ключи

Ключи шифруются Windows DPAPI с привязкой к вашей учётной записи пользователя: другой пользователь
той же машины их не прочитает, а скопированный файл бесполезен в другом месте. Приложение не хранит
сам материал ключа, и главного пароля, который можно потерять, нет.

Ключ прикрепляется только к исходящему запросу и никогда - к общему `HttpClient`, никогда не пишется
в лог, не попадает в сообщения об ошибках и нигде не сохраняется, кроме зашифрованного файла. Его
вводят в `PasswordBox`, который не участвует в data binding, - поэтому открытый текст не попадает ни
в визуальное дерево, ни в движок привязок, - и он очищается сразу после сохранения. `SecureStorageTests`
и `LiveProviderTests` проверяют эти свойства тестами, а не на веру.

## Тесты

```bash
dotnet test
```

834 теста на реальной мигрированной базе SQLite, реальном DPAPI и фейковых HTTP-обработчиках,
воспроизводящих записанные ответы провайдеров. Свежий клон без ключей и без сети проходит: восемь
тестов, которым нужен живой провайдер, сами пропускают себя и говорят об этом (826 прошло, 8
пропущено).

Чтобы прогнать и эти восемь, сначала положите ключ в переменную окружения:

```bash
set AICLIENT_TEST_OPENROUTER_KEY=sk-or-v1-...
```

```bash
dotnet test --filter "Category=Live"
```

Каждый задаёт одной модели одно слово при temperature 0 с лимитом 64 токена, так что счёт
незначителен. `AICLIENT_TEST_NVIDIA_KEY` то же самое для NVIDIA. Переменные только читаются и
никогда не записываются; ни один ключ не коммитится, и ничего в наборе не сохраняет его под
`%APPDATA%`.

## Стек

| Задача | Выбор |
| --- | --- |
| Рантайм | .NET 10: `net10.0-windows` для приложения и инфраструктуры, `net10.0` для домена |
| UI | WPF с MVVM, [WPF-UI](https://github.com/lepoco/wpfui) 4.3.0 для Fluent-оболочки |
| MVVM | CommunityToolkit.Mvvm 8.4.0, source generators вместо ручной разметки |
| Хранилище | EF Core 10 поверх SQLite, миграции применяются на старте |
| HTTP | `HttpClient` через `IHttpClientFactory`, именованный клиент на провайдера |
| JSON | `System.Text.Json`, общий экземпляр опций на каждый формат обмена |
| Markdown | Markdig парсит в блочную модель в Application; App рендерит элементами WPF |
| Секреты | DPAPI через `System.Security.Cryptography.ProtectedData` |
| Тесты | xunit.v3 |

WPF-UI победил двух очевидных альтернатив. **ModernWpf** - точный порт looks Windows 10 WinUI 2,
который отстаёт на версию: нет фона Mica, нет углов и работы с заголовком окна как в Windows 11 и
нет релизов с начала 2022 - оболочка родилась бы устаревшей и без апстрима. **MaterialDesignInXamlToolkit**
поддерживается лучше, но реализует Material Design от Google: клиент, который должен выглядеть как
поставляемый с Windows, вечно спорил бы с тенями, rippled и типографической шкалой библиотеки.
WPF-UI даёт Fluent-контролы, Mica и кастомный заголовок окна, за которые стоит дизайн, и следует
за целевой ОС: новое в платформе становится апгрейдом, а не переписыванием. Выбор не выходит за
слой App: сервис темы сидит за `IAppThemeService`, и замена библиотеки контролов не тронет остальные
три проекта.

## Структура проекта

```text
src/AIClient.Domain          Сущности, перечисления, модель графа, контракты провайдеров и хранилищ. Без зависимостей.
src/AIClient.Application     Сервисы, инструменты агента, граф-сервис, парсер markdown. Без HTTP и SQL.
src/AIClient.Infrastructure  EF Core, SQLite, провайдеры, DPAPI, рабочая область, файловое логирование.
src/AIClient.App             WPF: окна, представления, вью-модели, холст, конвертеры, поведения.
tests/AIClient.Tests         Набор тестов выше.
```

Зависимости указывают в одну сторону: App → Application → Domain, а Infrastructure реализует
интерфейсы средних слоёв и регистрируется одним вызовом `AddInfrastructure`. Проект App не ссылается
ни на тип провайдера, ни на `DbContext`: петля агента живёт в Application и доступна через
`IAgentService`. [ARCHITECTURE.md](ARCHITECTURE.md) содержит диаграмму, конвейер стриминга и
обоснования; [DEVELOPMENT.md](DEVELOPMENT.md) - миграции, конфигурацию и соглашения.

## Чего здесь нет в этой версии

Нет полноценного редактора кода - поверхность Code читает и показывает файлы, но не правит их, - нет
MCP, нет ввода картинок, нет плагинов и нет оболочки за `run_command`. Несколько агентов, фоновые
прогоны и панель просмотра дифов - следующие этапы: слоистость ровно за тем, чтобы они пришли без
переписывания, но пока их нет, и список выше - это и есть вся функциональность.
